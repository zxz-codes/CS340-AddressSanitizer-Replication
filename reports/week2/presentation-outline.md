## 一、论文与本组实验的对照

### 1.1 论文研究什么

- **问题**：C/C++ 程序的越界访问、释放后使用等内存错误很难发现，已有工具要么太慢，要么覆盖的错误类型不全（P，Sec. 1–2）。
- **方法**：ASan 在编译时给每次内存读写插入检查；运行时用影子内存记录每 8 字节应用内存能否访问，映射公式为 `(Addr>>3)+Offset`。堆、栈、全局对象周围放置被"下毒"的 redzone，释放的内存先进入 quarantine，暂不复用（P，Sec. 3.1–3.3）。
- **主要结果**：在 SPEC CPU2006 上平均变慢 73%（约 1.73 倍，Fig. 2）；只插桩写操作时平均变慢 26%；内存按 VmPeak 统计平均增加到 3.37 倍（Table 1）；在 Chromium 中发现 300 多个此前未知的缺陷（P，摘要、Sec. 4）。
- **论文测性能时的设置**：clang -O2、32 字节 redzone、关闭 malloc/free 时的栈回溯、quarantine 设为 0（P，Sec. 4）。

### 1.2 我们检验哪些结论

| 论文主张 | 论文证据 | 本组现有证据 | 当前判定 |
|---|---|---|---|
| 能检测堆、栈、全局越界和释放后使用（Sec. 3） | 机制说明 + 实际部署 | 自写的 5 类错误各跑 5 次，共 25 次全部报警且类别、源码行号正确；4 类合法/修复控制共 20 次全部正常退出（R3） | 只对测过的这些构造案例成立 |
| 运行开销约 1.73 倍（Fig. 2） | SPEC CPU2006 平均 | Olden 五个程序：modern 配置 1.884–24.728 倍，paper-like 配置 1.770–3.830 倍；等权平均分别为 7.663 和 2.243（R1、R7） | 原数值**无法判定**：负载、编译器、机器都不同 |
| 内存约 3.37 倍（Table 1） | VmPeak（虚拟内存峰值） | 测的是峰值 RSS（实际驻留内存），口径不同（R2、R5 Table 6） | **无法判定**：指标与负载都不同 |
| redzone 大小影响资源开销（Sec. 4.3） | 论文给出定性说明 | 只改最小堆 redzone（16/32/128 字节）的单因素实验，bisort、mst 各 5 次（R2、R5 Table 8） | 只对这两个输入有证据 |
| 只插桩写操作约 26% / Chromium 找到 300+ 缺陷 | Sec. 4、4.2 | 未做 | 不在本阶段范围 |

### 1.3 实验设置有哪些差异

| 项目 | 原论文 | 本组 | 对结论的影响 |
|---|---|---|---|
| 基准程序 | SPEC CPU2006 的 C/C++ 程序 | LLVM test-suite 中 Olden 的 5 个程序：bisort、mst、perimeter、treeadd、tsp，未改源码（R4） | **学校没有 SPEC CPU2006 授权，老师已允许改用开源基准**（R10）。负载不同，平均倍率不能当作复现误差 |
| 工具版本 | 2012 年的 ASan（LLVM 3.1 时期） | Clang/LLVM 14（R4、R5 Table 2） | 运行库默认参数和实现都变了 |
| 硬件与系统 | HP Z600，2 颗 4 核 Xeon E5620，24 GB 内存，64 位 Linux（P，Sec. 4） | 笔记本 i5-13500HX 上的 WSL2 Ubuntu 22.04，测量进程固定在 1 个逻辑 CPU 上（R5 Table 2） | 虚拟化、大小核映射、后台任务、温度等因素没有完全控制 |
| 编译选项 | clang -O2 | 两个版本都用 `-O2 -g -fno-omit-frame-pointer -fno-pie`；ASan 版关闭 use-after-return 和 use-after-scope（R4） | 尽量让插桩范围贴近 2012 年版本 |
| ASan 运行参数 | redzone 32、不做栈回溯、quarantine 0 | 两套：modern（保留运行库默认的 redzone、quarantine、分配栈记录，只关泄漏检测）和 paper-like（`redzone=max_redzone=32`、`quarantine_size_mb=0`、`malloc_context_size=0`）（R4） | paper-like 只是"接近"论文设置，不是 2012 年的二进制 |
| 内存指标 | 进程结束时 `/proc/self/status` 的 VmPeak | GNU time 的峰值 RSS（KiB）（R4） | 两者不能直接对比 |
| 覆盖范围 | 整个 SPEC 套件 + 只插桩写操作模式 | 5 个程序，只测完整读写插桩，每个配置 5 次（R1） | 代表性有限 |

### 1.4 哪些能对照，哪些不能直接等同

- **能对照的**：检测机制和报警行为；"先算每轮 ASan/native 倍率再汇总"的测量方法；"redzone 越大资源开销越高"这一类定性主张。
- **不能直接等同的**：
  - 7.663 或 2.243 和论文的 1.73 不是同一个量。我们的数是 5 个 Olden 程序的等权算术平均（R7），不是 SPEC 分数；
  - 峰值 RSS 和 VmPeak 不能对比；
  - 可执行文件大小：论文是 1.5–3.2 倍，平均 2.5 倍（P，Sec. 4）；本组是 68.74–86.96 倍（R5 Table 6、R9）。我们的原生程序去掉调试信息后只有约 16–20 KB，ASan 运行库这类固定成本占了大头，这是单次构建的观察值，不能拿来对比论文。

## 二、汇报提纲（约 6 页）

讲者分配待组内确定。每页的数字都写了来源，做 PPT 时照抄来源里的值，不要手动改写。

### 第 1 页　研究问题与目标

- **要讲的**
  1. C/C++ 的越界访问和释放后使用会导致崩溃或安全漏洞，而且常常在出错很久以后才表现出来。
  2. 论文提出 ASan，声称能在错误发生当下报警，平均只慢 73%（P，摘要）。
  3. 本组要回答两个问题：典型内存错误能不能被发现并定位？开启检测要付出多少运行成本？
- **图/案例**：论文标题 + 两个研究问题；也可以放一个 3 行的越界代码片段（取自 `examples/memory_cases.c`）。

### 第 2 页　ASan 原理

- **要讲的**
  1. 编译时在每次内存读写前插入一次检查。
  2. 影子内存：每 8 字节应用内存对应 1 字节影子，记录这 8 字节里有几个能访问（P，Sec. 3.1）。
  3. 对象周围放 redzone，访问到 redzone 就报警；释放的内存先进 quarantine，用来发现释放后使用（P，Sec. 3.3）。
- **图/案例**：论文 Fig. 1 内存映射示意；一张"对象 + 左右 redzone"示意图，可以用日志里真实的影子字节 `fa fa 00 00 00 00[fa]` 举例（R3，`correctness/heap-01.log`）。

### 第 3 页　实验方法 + 报错与修复演示

- **要讲的**
  1. 三组实验：检测验证（5 类错误 + 4 个合法控制，各 5 次，共 45 次）；性能测量（5 个程序 × 3 种配置 × 5 次 = 75 次）；redzone 扩展（2 个程序 × 3 档 × 5 次 = 30 次）（R1、R5 Table 1）。
  2. 判定标准：错误案例必须非零退出、错误类别对、调用栈里有源文件和行号；数组合法下标是 7，越界下标是 8（R5 Sec. 2）。
  3. 性能实验：每个配置先预热 1 次；用固定随机种子 340 打乱运行顺序；所有输出必须一致，并通过上游参考输出校验（R4、R5 Sec. 3）。
- **图/案例**：
  - 报错：`memory_cases heap 8` 的 ASan 报告，指出 `heap-buffer-overflow`、`memory_cases.c:12:39`，以及 "0 bytes to the right of 32-byte region"（R3，`correctness/heap-01.log`）。
  - 修复：`memory_cases fixed 8` 把下标限制在合法范围内，正常输出 `completed`（R3，`correctness/control-fixed-01.log`）。
  - 五类错误的结果表直接用 R5 Table 4（每类 5/5）。

### 第 4 页　当前结果：性能开销

- **要讲的**
  1. 倍率按同一轮的 ASan 时间 ÷ native 时间计算，再求均值和样本标准差（R10；方向 B 已独立复算 bisort、mst，与 summary.json 一致，R8）。
  2. paper-like 配置下 5 个程序在 1.770–3.830 倍之间；modern 配置在 1.884–24.728 倍之间，其中 treeadd 最高（24.728 ± 5.356）（R1）。
  3. 两套配置同时改了 redzone、quarantine、分配栈记录等多项参数，所以两者的差距**不能归因到某一个参数**；程序之间开销为什么不同，目前没有证据，先不下结论。
- **图/案例**：`reports/figures/runtime-ratios.svg`（R6），配 R1 的表格。
- **注意**：图中 treeadd 的柱子会把纵轴拉得很高，讲的时候先说明纵轴范围；均值不能读成论文 1.73 的复现误差。

### 第 5 页　redzone 扩展

- **要讲的**
  1. 只改一个参数：最小堆 redzone 取 16、32、128 字节。max_redzone 固定为 2048，quarantine 和分配栈记录固定为 0（R4）。
  2. bisort 的峰值 RSS 从 31.46 MiB（16 字节）到 40.46 MiB（32 字节）再到 94.49 MiB（128 字节），16→128 约 3.00 倍；mst 三档都在约 36.5 MiB，基本不变（R2、R5 Table 8）。
  3. 时间上，bisort 128 字节的均值较高（0.607 ± 0.127 s），但标准差大、只有 5 次，只能说"本次样本均值较高"，不说显著（R2）。
- **图/案例**：`reports/figures/redzone-memory.svg`（R6）。
- **注意**：这只检验了"redzone 设置会影响资源开销"这一局部结论，不估计真实漏洞的检出率，也不推广到其他程序（R5 Sec. 5）。

### 第 6 页　结论与局限

- **能说的**
  1. 5 类构造的内存错误全部被检测到并定位到源码行，合法和修复后的程序都正常退出（R3）。
  2. 在本机和 Olden 子集上，ASan 带来明显的时间与内存开销，大小随程序和运行参数变化很大（R1、R2）。
  3. 在 bisort 上，加大最小 redzone 明显增加内存；mst 上看不出变化（R2）。
- **不能说的（局限）**
  1. 没有复现论文 SPEC 上的 1.73 倍和 3.37 倍；只插桩写操作模式和 Chromium 的结果也没做（R5 Table 9）。
  2. 只有 5 个同属 Olden 的程序、每个配置 5 次，WSL 环境的干扰没有完全排除（R5 Sec. 6）。
  3. 合法控制全部通过，不等于证明 ASan 没有误报（R10）。
- **图/案例**：一张"能说 / 不能说"两栏对照表；最后一行写后续计划（加不同类型的程序和输入规模，在更安静的条件下复测短程序，R5 Sec. 6）。

## 三、老师可能问的三个问题及回答

### Q1　为什么不用论文的 SPEC CPU2006？换了基准还算复现吗？

学校没有 SPEC CPU2006 授权，老师已经允许改用开源基准，要求在周报和最终报告里说明（R10）。
我们用 LLVM test-suite 里的 Olden 子集：开源、能固定版本（commit `d52a93a8`），而且自带参考输出，可以校验结果对不对（R4）。
所以这是"用现代 ASan 在替代负载上检验同一类主张"，不是原数值的精确复现。
报告里也把 SPEC 上的 1.73 倍和 3.37 倍明确标为"无法判定"（R5 Table 9）。

### Q2　为什么你们测出来的开销和论文的 73% 不一样？这个倍率代表什么？

倍率的意思是：同一程序、同一轮里，开启 ASan 后的运行时间是原生版本的几倍，再对 5 轮求均值和样本标准差（R10）。
和论文不同，首先是因为比较的对象不同：程序（Olden 对 SPEC）、编译器（Clang 14 对 2012 年版本）、机器和运行参数都变了（1.3 节表格）。
接近论文参数时，我们的等权平均是 2.243 倍；它和 1.73 的数值差只是描述，不能当作同设置下的复现误差（R5 Sec. 6）。
modern 配置下 treeadd 达到 24.728 倍，但这一配置同时改变了多个参数，具体原因目前没有证据，我们不做猜测，后续可以用单因素实验再查。

### Q3　目前的结果能支持什么结论？还不能说明什么？

能支持：
- 对我们构造的 5 类错误，ASan 能报警并给出源码行（R3）；
- 在本机和这 5 个程序上，开启 ASan 有可测量、可追溯到日志的时间和内存开销（R1、R2）；
- 在 bisort 上，最小 redzone 越大，峰值 RSS 越高（R2）。

不能说明：
- 论文 SPEC 上的平均数值；
- 内存是否也是 3.37 倍（我们测的是 RSS，不是 VmPeak）；
- 结论能否推广到其他程序和机器；
- ASan 没有误报（R5 Table 9、R10）。

### 备选问题（时间允许再准备）

- **"RSS 和 VmPeak 有什么区别？"**：VmPeak 是虚拟地址空间峰值；RSS 是实际占用的物理内存峰值。64 位 ASan 会映射很大的影子虚拟地址区域，所以两者差别可能很大，不能互换（R5 Sec. 4）。
- **"为什么不把检查全关掉再测，开销会更小？"**：缩小 redzone 会减少保护范围；关掉 quarantine 可能漏掉释放后使用；关掉分配栈记录会让报告信息变少。论文的性能设置本身就是一种取舍，所以检测实验用的是保留诊断信息的 modern 配置（R5 Sec. 4；P，Sec. 4.3）。
